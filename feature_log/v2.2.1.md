# FlightScanner v2.2.1 更新说明

**发布日期**: 2026-11-06

**版本**: v2.2.1

---

## 版本概述

v2.2.1 是可靠性与数据口径修复版本，重点解决错误票价入库、采集批次不一致、通知部分成功被误判为送达、买入计划重复触发、往返复盘混入其他产品，以及路线更新绕过校验等问题。本版本同时移除企业微信运行时接入，保留 Email、Telegram 和飞书。

---

## 一、票价与历史统计口径

- 去哪儿国际单程不再通过假往返请求获取往返总价并冒充单程价；该降级路径明确返回无可用报价。
- Streamlit 周末雷达删除确定性随机价格与虚构均价，没有真实历史数据时不再生成业务事实。
- 当前采集批次不再参与自身的历史均值、历史低点和趋势统计；`near_30d_low` 至少需要三个历史批次。
- 普通模式拒绝零元、负价和明确售罄报价；去重键包含币种、回程航班和回程日期，避免不同产品误合并。
- 去哪儿 wbdflightlist 中转行程保留双航段号，周末雷达不再把中转误判为直飞。

## 二、采集、过滤与 Cookie 生命周期

- 同一路线采集互斥；同一共享爬虫跨路线串行，不同平台仍可并行。
- 精准匹配、机场和时间窗过滤先于 Top-N 截断，避免符合条件的报价在过滤前被截掉。
- 普通路线与精准航班均整批原子保存，任一条失败时整批回滚，不再出现半批数据。
- 实时路线过滤启用严格模式：配置了机场或时间窗但报价缺少合法字段时，该报价不会入库。
- 去哪儿与携程的 Browser/Context 生命周期分离，Cookie 更新只重建 Context，不再泄漏或误关 Browser。
- 登录脚本和 Cookie 上传仅接受真实认证状态，采用 `0600` 临时文件、`fsync` 和原子替换；失败不会覆盖旧 Cookie，日志不输出 Cookie 值。
- 去哪儿 HTTP、移动端和 JSON 解析失败会抛出明确异常；只有有效响应确认无航班时才返回空列表，所有降级路径失败不再伪装成正常空结果。

## 三、通知与买入闭环

- 同一提醒使用持久化 `event_id`，`NotificationLog` 按事件和渠道记录成功或失败。
- 已成功渠道跳过，失败渠道在后续采集或维护任务中补发；所有当前配置渠道成功后才进入冷却。
- 普通路线通过 `pending_notification_event_id` 跨批次保留待投递事件；买入计划使用稳定触发时间派生事件 ID。
- 保存通知设置后，运行中的调度器会热重建通知器，无需重启进程。
- 买入计划通过数据库条件更新完成 `pending → triggered` 原子认领，避免并发检查或旧 Session 重复触发。
- 无报价或报价全部过滤时仍检查买入截止时间；每 15 分钟执行计划维护，不再只依赖每日任务。
- 补发通知使用真实触发价；跨起飞日但未送达的计划继续重试，不会被静默过期。
- 往返买入记录保存 `return_flight_id`，复盘同时匹配去程、回程、币种、舱位和余票，不再用路线最低价替代同一产品。
- 缺少完整产品标识的旧往返记录，以及最后可比报价距截止点超过 48 小时的记录，返回数据不足，不生成确定节省金额或 verdict。

## 四、API、雷达与部署可靠性

- 路线创建与 PATCH 共用目标价、日期和 HH:MM 时间窗校验；PATCH 基于数据库现有值与请求合并后的完整路线验证，失败时不发生部分更新。
- 往返路线必须有回程日期，回程不得早于去程，目标价必须大于零；重复提交相同启停状态不再重建调度。
- 设置接口的数据库连接串隐藏密码。
- 周末雷达在扫描排队后每 5 秒刷新，包括后台标签页；检测到 `latest_scan_at` 变化后结束等待，120 秒后提示手动刷新。
- 主程序发生致命异常时，清理资源后重新抛出，不再以成功状态退出。
- 公网部署文档新增 nginx Basic Auth、密码文件权限和强制 HTTPS 要求；Basic Auth 不得用于保护明文 HTTP。

## 五、企业微信接入移除

- 删除企业微信通知器、运行时工厂分支、环境变量、设置接口和前端配置卡片。
- 当前可用渠道为 Email、Telegram 和飞书。
- 历史提醒页仍保留 `wecom → 企业微信` 名称映射，仅用于既有日志审计展示。
- 旧 `.env` 中的 `WECOM_WEBHOOK_URL` 不再生效，可由部署者自行清理；本版本不会改写用户真实环境文件。

## 六、数据库兼容与历史数据处理

本版本通过幂等迁移新增：

- `routes.pending_notification_event_id`
- `notification_logs.event_id` 及事件/渠道索引
- `purchase_records.return_flight_id`

旧库会在启动时自动补充上述结构，不需要手动删库。

早期去哪儿国际单程错误价格缺少可靠的原始请求类型标记，无法安全地区分真实单程价与被误存的往返总价。因此本版本只阻止新增污染，不自动修改旧记录：

1. 升级前备份数据库。
2. 将升级前、国际航线、`trip_type=oneway`、来源为去哪儿的报价列为人工审计候选。
3. 能取得原始订单或平台页面证据的记录逐条核对；无法验证的记录应标记无效或排除出统计，不应继续作为决策事实。
4. 不得统一除以二，也不得静默重标为往返价；这两种操作都会制造新的错误数据。

旧往返买入记录若缺少回程产品标识，会显示数据不足，不会通过放宽匹配条件生成看似精确的复盘结论。

## 七、验证结果

- 后端全量测试：**835 项通过**，覆盖路线创建/PATCH、买入 API、通知重试、买入状态机、往返复盘、去哪儿采集与运行时可靠性。
- 前端 TypeScript 生产构建与 ESLint 均通过；构建仅有现存的大包体积提示。
- 本次修改的 Python 文件通过 Ruff 功能性错误检查，`git diff --check` 通过。全仓 Ruff 仍存在大量历史风格与可维护性问题，本版本未借修复发布进行无关清理。
- 浏览器验收周末雷达筛选、扫描排队/超时状态及设置页渠道展示，控制台无错误。
- 未把单元测试视为真实平台采集保证；去哪儿、携程、同程的在线可用性仍取决于平台页面、反爬策略和有效 Cookie。
