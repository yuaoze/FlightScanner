# FlightScanner v2.2.0 更新说明

**发布日期**: 2026-08-13

**版本**: v2.2.0

---

## 版本概述

v2.2.0 新增「买入闭环」，把监控从"看价格"延伸到"买之后"：支持买入计划（目标价/截止时间触发通知）与一键记录买入，买后复用现有采集零成本持续监控，航班起飞后自动生成买点分析（AI 评价 + 量化统计），并把每次买入的经验教训沉淀到经验库，反哺后续 AI 简报，形成「计划 → 买入 → 监控 → 分析 → 经验」的完整闭环。

---

## 一、买入计划与一键买入

### 1.1 买入计划（状态机）

在路线详情页可创建买入计划，二选一或同时填写：

- **目标买入价**：每次采集后若当前最低价 ≤ 目标价即触发
- **最迟买入时间**：到达截止时间即触发

计划状态机为 `pending → triggered（通知用户确认）→ converted / cancelled / expired`。触发后仅通知并在前端标记待确认，不自动创建买入记录——实际成交价需用户确认；触发后 48 小时未确认或路线已起飞仍未触发则自动置为 expired。

### 1.2 记录买入

路线详情页新增 amber 色「💰 记录买入」主按钮：

- 一键买入自动取该路线**最新批次跨平台最低价**预填，可修改为实际成交价
- 明确区分单人可比票价与订单实付总额，并记录币种、舱位、人数、真实成交时间及报价快照
- 计划触发后确认成交同样生成买入记录（`purchase_type` 区分 `instant` / `planned`）

## 二、买后监控与买点分析

### 2.1 零成本买后监控

买入后复用路线现有采集（price_history 持续写入），不增加任何额外抓取。分析时先按采集批次聚合可比最低价，再取 `买入时间 → 实际起飞时间` 价格窗口计算统计：

- 买后最低价 / 最终价（起飞前最后采集价）
- **后悔成本** = 买入价 − 买后最低价（跌幅低于 5% 显著性门槛记 0，过滤正常波动）
- **相对节省** = 最终价 − 买入价
- 样本数按独立采集批次计算，同批次多平台/多航班报价不会虚增样本或污染最终价

### 2.2 买点分析（AI + 规则降级）

航班起飞后由每日任务为未终评记录生成或重算分析，也可在详情抽屉手动重新生成（未起飞时基于已有数据并标注"起飞前预判"）：

- 分析状态区分 `provisional / final / insufficient`，并记录样本数、覆盖时长与 `good / limited / insufficient` 数据质量
- verdict 四级评分按相对票价比例判定，避免固定金额门槛在高低价航线上失真
- LLM 输出结构化 JSON：总评、时机评估、关键教训；无 API key 或数据不足时降级为规则模板
- 起飞后终评才纳入 KPI；明确样本不足后不再每日重复分析

### 2.3 买入记录页

新增「💰 买入记录」页（`/purchases`），含两个 Tab：

- **买入记录**：KPI 卡片（累计节省 / 平均买点评分 / 持有中）+ 计划区（触发中的计划 amber 高亮待确认）+ 记录表格（当前价、相对涨跌、verdict 徽章）
- **详情抽屉**：Recharts 折线图（买后价格序列 + amber 虚线标记买入价 + emerald 虚线标记买后最低价）、统计卡、AI 分析卡、重新分析按钮

## 三、经验沉淀与反哺

### 3.1 经验库

高质量终评可从 AI 关键教训中提炼 1–2 条经验写入经验库；独立证据表保证同一买入不会重复刷票，重分析会替换旧证据。手工经验标记为未验证。经验库 Tab 支持手动新增 / 编辑 / 归档 / 删除，按 `timing / route / holiday / general` 分类。

### 3.2 经验反哺 AI 简报

生成 AI 简报时，除进化引擎上下文外追加该路线的历史买入经验（匹配路线 pattern 或"通用"的 active 经验最多 5 条，附独立证据次数）。经验作为有边界、长度受限的不可信用户数据提供，不进入 system 指令层，避免持久化提示注入。已覆盖全部 4 个简报生成通道。

涉及文件：

- `src/flightscanner/core/services/purchase_service.py`

## 四、API 与数据模型

### 4.1 新增 5 张表（兼容迁移）

- `buy_plans`：买入计划（目标价 / 截止时间 / 状态机 / 触发时价格）
- `purchase_records`：买入记录（成交价 / 舱位 / 张数 / 来源计划 / holding|completed）
- `buy_point_analyses`：买点分析（与买入记录 1:1，窗口统计 + verdict + AI 文本）
- `experience_entries`：经验库（路线 pattern / 分类 / 证据数 / active|archived）
- `experience_evidence`：经验与独立购买证据关联，防止重复计数

迁移启用并校验 SQLite 外键，增加计划转换唯一索引、路线/报价快照及分析质量字段；失败时停止启动，避免静默形成半迁移数据库。含买入账本的路线采用软删除，历史购买和分析不会随监控路线被清理。

### 4.2 新增 12 个 API 端点

- 买入：`POST /api/purchases/instant`、`GET /api/purchases`、`GET /api/purchases/{id}`（含买后价格序列）、`POST /api/purchases/{id}/analyze`
- 计划：`POST /api/plans`、`GET /api/plans`、`DELETE /api/plans/{id}`、`POST /api/plans/{id}/confirm`
- 经验：`GET/POST /api/experiences`、`PUT/DELETE /api/experiences/{id}`

涉及文件：

- `src/flightscanner/api/routers/purchases.py`

## 六、可靠性与性能加固

- 计划触发与通知投递分离持久化，全渠道失败不再误记成功，后续日任务可补发
- 置顶航班采集同样检查买入计划；进化回测失败不再阻断购买日任务
- 列表接口增加 `offset / limit`，单次最多 500 条并预加载展示关系
- 最新价格始终按真实采集时间定位批次，不再对不可排序的 `batch_id` 取最大值
- 监控总览接口改为索引友好的两阶段聚合，避免价格历史增长后的平方级自连接
- 监控页、买入记录、计划与详情增加明确错误态和重试入口，不再把接口失败伪装为“暂无数据”

## 八、2026-08-17 增量更新：同程旅行价格监控

### 8.1 第三采集平台完整接入

新增 `tongcheng`（展示名「同程旅行」）作为第三个正式价格源，并接入注册表、配置校验、调度器、CLI、Cookie 管理、路线详情和价格趋势：

- 国内航线使用同程国内机票搜索链路
- 港澳台及国际航线自动切换到同程国际机票链路
- 单个平台失败不会阻断其他平台；调度器统一应用超时、重试次数和单平台结果上限
- 运行中修改平台配置后可安全重建爬虫实例，无需用“保存成功但实际未启用”的旧状态继续运行
- 去重键补充方向与出发日期；往返组合禁止跨平台拼接，避免把其他平台回程误标为同程价格

### 8.2 国际价格与往返口径

同程国际采集复用官网页面发起的 `/miflightapi/ts/list` 与产品详情请求，并明确价格口径：

- 记录成人经济舱公开可售的**单人含税价**，不把未税票面价、会员专享价或券后价混入趋势
- 轮询响应按“最新完整快照”处理，避免把早期瞬时低价错误保留为最终结果
- 国际往返读取官方 RT 产品详情中的真实去程、回程和整套含税价，不再用两个独立单程最低价相加
- 支持中转航班、跨日起降、航站楼回退及有限余票；缺失关键航班号或无效价格的记录会被跳过
- 正常无票、登录失效、验证码/风控和接口协议变化会给出不同告警或错误原因，不再都伪装成“0 条航班”

### 8.3 同程扫码登录与 Cookie 安全

设置页与 Streamlit Cookie 管理器新增同程扫码刷新：

- 使用同程官方微信 OAuth 二维码，请使用微信“扫一扫”完成登录
- 登录流程使用强会员标记确认成功，匿名 Cookie、跳转或普通 302 响应不会被误判为已登录
- 仅保存 `ly.com` 域 Cookie，并采用临时文件 + 原子替换写入；失败或超时不会覆盖旧 Cookie
- API 登录状态转换加锁并支持重复请求保护，二维码读取失败会明确结束任务
- 同程 Cookie 支持手工上传、删除和运行中热重载

### 8.4 立即采集状态与可视化闭环

“立即采集”从仅返回 `queued` 升级为可追踪任务：

- `POST /api/routes/{route_id}/scrape` 成功排队时返回 `task_id`
- `GET /api/routes/{route_id}/scrape/status` 查询路线最新任务
- `GET /api/routes/{route_id}/scrape/{task_id}` 精确查询本次任务
- 状态包含 `queued / running / completed / partial / failed`，并按平台返回结果数、告警和错误
- 前端轮询任务终态后立即刷新价格历史、批次、航班、日历和路线缓存，并展示每个平台的采集结果
- 批次航班接口增加 `source` 筛选，选择同程批次时不会混入去哪儿或携程航班
- 价格走势图增加同程独立颜色和来源标签；新平台只有一个时间点时显示数据点，不再因无折线段而不可见

### 8.5 测试与文档

新增同程解析、扫码登录、注册/配置、调度集成、来源筛选和采集任务状态测试；覆盖国内/国际单程、官方往返产品、异常分类与 Cookie 原子写入。前端任务轮询、缓存刷新和趋势单点展示通过生产构建与目标 ESLint 验证。更新 `README.md`、`.env.example`、2C4G 部署文档与 Cookie 忽略规则。

本次增量最终验证：后端 **466 项测试全部通过**；前端生产构建及本次变更文件 ESLint 通过；同程核心爬虫与测试通过 Ruff，核心登录与爬虫模块通过 Mypy。

### 8.6 当前边界

- 同程国际当前监控 1 名成人的经济舱公开价，不覆盖儿童、婴儿及公务舱/头等舱
- 国际往返最多查询最低 5 个 RT 候选详情，以控制请求量；国内往返仍由两个官方单程结果组成参考组合
- 微信需已绑定同程账号；Cookie 有效也不能保证每次采集都避开站方实时风控
- 立即采集任务状态保存在进程内存中，最多保留最近 100 条，API 重启后不会恢复
